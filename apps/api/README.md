# Atcraft Manufacturing ERP - backend

FastAPI modular monolith. The repository-wide rules are in the root
[`CLAUDE.md`](../../CLAUDE.md); the schema and cross-module contract in
[`docs/database.md`](../../docs/database.md). Run every command below from the
repository root through `make <target>` (macOS/Linux) or `.\make.ps1 <target>`
(Windows); they `cd` here and use `.venv`.

## Set up

```bash
make install        # python -m venv .venv, then scripts.install_requirements, then npm ci, then git hooks
make dev            # Postgres + Redis in Docker (Windows: then .\make.ps1 dev-api in another terminal)
make migrate
make seed           # roles, permissions, units, warehouse types
make demo-data      # optional: a working business for every screen
```

`install` uses `python -m scripts.install_requirements requirements-dev.lock`
rather than `pip install -r` because the lock files are resolved on Linux and
pin `uvloop`, which has no Windows build. The installer drops the pins the
platform cannot use and installs everything else with `--require-hashes`
intact. `make lock` regenerates both locks after editing `pyproject.toml`.

Configuration is a single `.env` at the repository root (see `.env.example`),
read by `src/core/config.py` and by Docker Compose. Deployments never use it.

## Layout

```
src/core/           config, database, security, permissions, errors, messages,
                    constants, responses, pagination, cache, logging, deps
src/common/         base repository, document numbering
src/modules/<name>/ models · schemas · repository · service · router
src/workers/        Celery app and tasks
scripts/            export_openapi, install_requirements, reset_database
migrations/         Alembic
tests/              unit (no database) · integration · api
```

## Checks

```bash
make test-unit          # pytest tests/unit -q
make test-integration   # pytest tests/integration tests/api -q  (needs make dev)
make lint               # ruff + mypy, then the frontend linters
make contract-check     # openapi.json and the generated frontend types are current
make check              # everything CI runs
```

`openapi.json` at the repository root is generated by
`python -m scripts.export_openapi` (`make contract`), and the frontend's types
are generated from it. An API change that is not followed by `make contract`
fails the pre-push hook and CI.
