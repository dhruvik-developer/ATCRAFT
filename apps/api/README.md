# Atcraft Manufacturing ERP - backend

FastAPI modular monolith. The repository-wide rules are in the root
[`CLAUDE.md`](../../CLAUDE.md); the schema and cross-module contract in
[`docs/database.md`](../../docs/database.md). Run every command below from the
repository root through `make <target>` (macOS/Linux) or `.\make.ps1 <target>`
(Windows); they change into the appropriate application directory. On
macOS/Linux, activate `apps/api/.venv` before running Python targets; the
PowerShell wrapper selects that virtual environment automatically.

## Set up

Follow the root [setup instructions](../../README.md#quick-start) to create
the root `.env`, install dependencies and start PostgreSQL and Redis. For a
complete local UI testing dataset, run:

```powershell
.\make.ps1 seed-local    # macOS/Linux: make seed-local
.\make.ps1 dev-api       # separate terminal
.\make.ps1 dev-web       # separate terminal
```

`seed-local` upgrades the local database, loads baseline and demonstration data,
refreshes stock-report summaries and generates the demonstration invoice and
credit-note PDFs. It preserves existing records and passwords. The database
must already exist, both database URLs must name the same loopback target,
and `APP_ENV` must be `development` or `test`. The initial administrator
password is displayed once; change it at first sign-in. See the
[local seed guide](../../docs/local-seed-data.md) for details and custom options.

For baseline reference data alone, use `make migrate` followed by `make seed`.
`make demo-data` remains available for individual demonstration stages after
baseline seeding; `seed-local` is the complete local installation entry point.

`install` uses `python -m scripts.install_requirements requirements-dev.lock`
rather than `pip install -r` because the lock files are resolved on Linux and
pin `uvloop`, which has no Windows build. The installer drops the pins the
platform cannot use and installs everything else with `--require-hashes`
intact. `make lock` regenerates both locks after editing `pyproject.toml`.

Configuration is a single `.env` at the repository root (see `.env.example`),
read by `src/core/config.py` and by Docker Compose. Deployments never use it.

## Layout

```
src/core/           config, database, security, permissions, errors, messages,
                    constants, responses, pagination, cache, logging, deps
src/common/         base repository, document numbering
src/modules/<name>/ models · schemas · repository · service · router
src/workers/        Celery app and tasks
scripts/            export_openapi, install_requirements, seed_local, reset_database
migrations/         Alembic
tests/              unit (no database) · integration · api
```

## Checks

```bash
make test-unit          # pytest tests/unit -q
make test-integration   # pytest tests/integration tests/api -q  (needs make dev)
make test-cov           # complete backend suite with the configured coverage floor
make lint               # ruff + mypy, then the frontend linters
make contract-check     # OpenAPI, Postman and generated frontend types are current
make check              # application checks; CI also verifies deployment images and browser journeys
make clean              # generated builds, reports and caches; preserves data and dependencies
```

`openapi.json` at the repository root is generated by
`python -m scripts.export_openapi` (`make contract`), and the frontend's types
are generated from it. An API change that is not followed by `make contract`
fails the pre-push hook and CI.
